# Changelog

All notable changes to Touchy-Pad — firmware plus the host libraries (Python
`touchy-pad`, Rust `touchy-pad` crate, OpenDeck plugin) — are recorded here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Versions come from the repo-root `VERSION` file, which is shared by the firmware,
the Python package and the Rust crate.

The deep, stage-by-stage history — *why* a change was made, including hardware
findings and rejected designs — lives in [`docs/design.md`](docs/design.md).
Entries here begin at 0.3.5; earlier releases predate this file and are covered
by that design history and the git tags (`git tag -l`).

## [Unreleased]

### Added

- **`FontSize` / `FONT_SIZES`: the list of font sizes the device can render.**
  `label(…, font_size=…)`, `span(…)`, `style(font_size=…)` and
  `build_property_override(…, "text_font", …)` now take a pixel size from a
  published set — `FONT_SIZES == (8, 14, 16, 24, 30)` (`FontSize.FONT_SIZE_*`; 8
  is LVGL's UNSCII 8 for the LED panels, the rest Montserrat) — and raise
  `ValueError` for anything else. Previously any other number silently rendered
  at the theme default (Montserrat 14), so `font_size=20` looked "supported" but
  came out at 14 px. The list is generated from the proto enum, so Python, Rust
  and firmware can never disagree.
- **Change a label's font size at runtime** — no screen re-upload:
  `pad.set_properties([build_property_override("title", "text_font", 30)])`
  (Python), `pad.set_font_size("title", FontSize::FontSize30)` (Rust, the
  crate's first property-override helper), `touchy property set title text_font
  30 --int` (CLI), or `{"setProperties":{"props":[…{"propertyName":"text_font",
  "fontSizeValue":30}]}}` over the JSON network API. The change is sticky
  (survives screen reloads and page swaps) and repaints immediately; `0`
  restores the theme font.
- The Rust crate gained `Touchy::set_properties` / `Touchy::set_font_size` and
  re-exports `FontSize` + `FONT_SIZES`.
- **A 24 px Montserrat font** is now compiled in (`CONFIG_LV_FONT_MONTSERRAT_24`),
  so the published set grew to `FONT_SIZES == (8, 14, 16, 24, 30)` and
  `font_size=24` / `FontSize.FONT_SIZE_24` render for real instead of silently
  falling back to 14 px.
- **`just firmware-report`** prints the flash/RAM usage for the currently
  configured board+target: IDF's memory-type summary plus an app-partition line
  with the bytes used, the **percentage full** and the bytes free. The helper is
  `bin/firmware-report.sh` (portable, like `bin/flash.sh`).
- **Rich text: the `span_group` widget** (`Widget.kind.span_group`, `span()` /
  `span_group()` in `touchy_pad.api`). A paragraph built from independently
  styled *runs* — per-run text colour **and** font size — with `overflow`
  (clip / ellipsis), a line cap (`max_lines`) and horizontal `text_align`. This
  is the recommended way to put several colours in one text layout, and live
  updates stay cheap: a `text` property override whose value is recolour markup
  (`"#RRGGBB run# rest"`) is re-parsed into the runs on the device, one RPC per
  frame. The host-side mirror of that parser is `parse_recolor_markup()`.
- A `span` demo/regression page ships with `touchy screen demo` (`touchy_pad.pages.span`),
  so the on-device page cycle is now `span` → `test` → `trackpad`.
- **The `touchy-pad` crate is crates.io-ready.** The prost bindings are
  **checked in** (`rust/touchy-pad/src/proto/touchy.rs`, regenerated by the new
  `rust/proto-gen` workspace member), so building the crate needs no `protoc`,
  no build script and no `prost-build` — matching the Python package, whose
  generated `_pb2` modules already ship inside the wheel. First published as
  **0.3.9** on 2026-11-15, so `cargo add touchy-pad` now works.
- Runnable Rust examples: `cargo run --example {discover,screen,events,image_cache}`.
- `# Errors` sections on every fallible public API (enforced by
  `clippy::missing_errors_doc`), `#[doc(alias)]` aliases on the main entry
  points, and a "For AI agents" block in the crate docs.
- `release.yml` publishes the crate to crates.io on every GitHub release —
  via the `CARGO_REGISTRY_TOKEN` secret, or crates.io trusted publishing (OIDC)
  when that secret is absent. Skips a version that is already published.
- `just rust-gen-proto`; `just build-proto` now refreshes the Python, C **and**
  Rust bindings in one go.

### Changed

- The published crate also ships `tests/**` and `examples/**`, and docs.rs is
  built with the `serial` feature so the serial transport is documented.
- The `tools/autopage` submodule was removed — it was reference-only, and its
  *nested* `autopage-recipes` submodule was pinned to a revision that no longer
  exists upstream, which broke `git clone --recurse-submodules` and every
  `cargo` `git =` dependency on this repository.

### Fixed

- **Multi-coloured text no longer corrupts the line it wraps on.** With
  `label(recolor=True)`, a `#RRGGBB text#` run that an automatic line break fell
  *inside* used to lose its colour, swallow the next word, let the line overrun
  its box and draw the seam glyphs twice (overlapping) — a defect in LVGL's own
  label recolour parser, which loses its command state at the start of a line
  and when a draw pass skips to its first visible line (LVGL #4599 / #8547).
  The firmware now renders that same markup through an LVGL **span group**, so
  the colour runs are real styled runs with no in-string state to lose; **no host
  change is needed** and the wire format is unchanged. Only the two *scrolling*
  long modes (`SCROLL` / `SCROLL_CIRCULAR`) still use LVGL's label path — a span
  group cannot marquee, and an unwrapped scrolling line never hit the bug.
  Note this can shift a wrapping recoloured label's line breaks by a word versus
  previous firmware (the old breaks were computed from the mis-measured line).
- `touchy-pad` (Python): `TouchyClient.file_save()` now retries once when
  `FileOpenWrite` reads a stale `NOT_FOUND` (or an `OK` with no handle) left in
  the device's reply FIFO by a host that was hard-killed mid-RPC. A genuine open
  failure is `RESULT_IO_ERROR`, so this cannot mask a real error. Before the fix
  the misread reply also leaked a device-side write transaction (visible as
  `fs_open_write: stale transaction detected …` on the next session) and the
  write never completed. Also: `touchy_open()` no longer accepts a leftover `OK`
  reply as board info — a default reply (`protocol_version == 0`, 0×0 panel) is
  flushed and retried once, so callers stop seeing a phantom 0×0 board; a
  successful `FileOpenWrite` reply without a handle is rejected instead of
  becoming handle `0`; and concurrent `file_save()`s from different threads are
  serialised so they can't abort each other's transaction.
- `touchy-pad` (Rust): `Touchy::file_write_raw()` gets the same flush-and-retry
  on a desynced `FileOpenWrite`, via the new crate-internal
  `Client::flush_stale_frames()`.
- `touchy-pad`: mutes lints for the generated protobuf module, fixing a
  `just rust-lint` failure that newer clippy raised on it
  (`clippy::large_enum_variant`).

### Documentation

- README: a new ["want to build your own app?"](README.md#want-to-build-your-own-app-you-dont-need-to-clone-this-repo)
  section sends people who just want to *use* Touchy-Pad to the published
  packages (`pip install touchy-pad` / `cargo add touchy-pad`) instead of a
  source checkout, with PyPI / crates.io / docs.rs badges at the top and an
  explicit list of when you *do* want the source (firmware, wire protocol, the
  libraries themselves, PRs).

## [0.3.9] - 2026-11-06

### Fixed

- Labels honour `scroll_speed_px_s` exactly: the firmware now computes the lap
  duration from the real text length instead of LVGL's encoded speed, which
  capped the lap at ~10 s and made long labels on small displays scroll far too
  fast (`docs/plans/label-scroll-speed.md`).

### Changed

- Every workflow declares least-privilege `permissions:`.

## [0.3.8] - 2026-11-04

### Documentation

- Revised the security policy and vulnerability-reporting instructions
  (`SECURITY.md`).

## [0.3.7] - 2026-11-04

### Fixed

- CI: validate and repair the cached ESP-IDF Python environment, which failed
  with `Unable to import the rich module`.

### Changed

- Bumped the `tools/autopage` submodule.

## [0.3.6] - 2026-11-06

### Added

- Custom label scroll speed: `Label.scroll_duration_ms` (ms per lap) and
  `Label.scroll_speed_px_s` (px/s), plus the host DSL arguments
  (`Widget.Version` 29 → 30).

### Fixed

- LED-matrix boards default to 10 % brightness when the host has never set
  `backlight_level`.
- The demo screen works on touch-less (LED matrix) boards.

### Changed

- Rust dependency updates.

## [0.3.5] - 2026-11-04

### Added

- Inline label recolouring (`Label.recolor`: `#RRGGBB` runs inside one string)
  and a 512-byte cap on property-override strings.

### Fixed

- Host-driven invalidations now wake the LVGL task, so panels repaint as soon as
  the host writes instead of waiting for the port's idle sleep — a large,
  visible UI latency improvement (Stage lb16 phase 2).
- USB devices attached *after* a long-running host process started are found
  again (libusb caches its device list per context).

### Removed

- The display-width workaround.

### Changed

- The `tools/googly-vr` and `tools/voicebot` submodules were dropped; both apps
  moved to their own repositories.
- Dependency security updates.
